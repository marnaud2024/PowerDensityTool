Power Density Tool - guia do programador
GPEC / UFC
========================================

Este e o guia de quem vai mexer no codigo: onde ficam as coisas, o que cada
arquivo faz, o esquema da base de dados, as estruturas que passam de uma camada
para outra, como a interface e montada, as armadilhas que a gente ja levou, e
como estender e compilar. A ideia e que qualquer pessoa consiga ler, manter ou
evoluir o projeto sem precisar adivinhar nada.

O ambiente e MATLAB, com App Designer feito na mao (sem .mlapp). Foi testado com
o MATLAB em C:\Program Files\MATLAB\bin\matlab.exe.


1. Estrutura de pastas
----------------------
PowerDensityTool/

    Catalog.xlsx                 a base de dados unica (varias abas - ver secao 3)
    plecs_mosfets/
      GeneSiC/   *.xml           modelos termicos PLECS da GeneSiC

    setup/MyAppInstaller.exe     o instalador (o unico arquivo a distribuir; gerado

    teoria/                      o relatorio LaTeX da teoria (fonte + PDF)
    THEORY.txt                   a teoria em texto corrido

                                 Full-Data Steinmetz), de onde sairam as abas
                                 Magnetics_CurveFit e Steinmetz do Catalog.xlsx

Uma coisa dos namespaces do MATLAB: pastas que comecam com '+' sao pacotes. Uma
funcao em src/+pdpwr/+loss/mosfet.m e chamada como pdpwr.loss.mosfet(...). A pasta
'+test' e o pacote 'test', entao os testes rodam como test.regression. (E ela
precisa se chamar '+test' mesmo, com o mais; se for so 'test', o MATLAB nao acha o
namespace.)


2. Como os dados fluem
----------------------
   Catalog.xlsx
        |  load_catalog
        v
   app.Catalog (um struct com as tabelas)
        |
   +-----------------------------------------------------------+
   | Aba MOSFET/Diodo:                                          |
   |   catalog -> +loss (perda por dispositivo)                 |
   |           -> +design.heatsink (dissipador por dispositivo) |
   |           -> hsAll (struct array: dispositivo + dissipador)|
   |           -> app.set_results('mosfetI'/'mosfetII'/'diode') |
   | Aba Indutor/Trafo:                                         |
   |   catalog -> +design.inductor/transformer (varre materiais)|
   |           -> records (struct array dos projetos validos)   |
   |           -> app.set_results('inductor'/'transformer')     |
   +-----------------------------------------------------------+
        |
   Aba Power Density:
        app.get_results(...) de cada familia
        -> pdpwr.density(comp, opts) -> res (eff/powerDens/loss/lossDens)
        -> grafico + tabela + output/power_density_results.xlsx

A classe PowerDensityApp guarda o resultado de cada aba em app.Results.<nome>, via
set_results/get_results, e a aba Power Density le esse cache na hora de combinar.


3. O esquema do Catalog.xlsx (abas e colunas)
---------------------------------------------
MOSFETs_PLECS
   Manufacturer, PartNumber, Package, Vds_max_V, XML_File, Has_BodyDiode_XML,
   Technology (= 'SiC'; reservado para 'Si'/'GaN' no futuro - define a cor do scatter)

Diodes
   Manufacturer, PartNumber, Package, Vrev_V, I_A,
   Rd_a, Rd_b, Rd_c   (R_d(Tj) = a*Tj^2 + b*Tj + c)
   Vto_a, Vto_b, Vto_c (V_TO(Tj) = a*Tj^2 + b*Tj + c)
   PerLeg ('SIM'/'NAO'), Technology (= 'SiC')

Heatsinks
   Manufacturer, Profile, ProfileNum, Rth_natural_CW, Rth_forced_CW,
   Height_mm, Width_mm, Convection_Notes (ex.: "5 m/s" para a forcada)

Cores_Magmattec
   Material ('MMT002'/'MMT026'/'MMT034'/'MMT052'), Product, AL_nHesp2, Le_mm,
   Ae_mm2, Ve_mm3, OD_mm, ID_mm, HT_mm

Cores_Magnetics  (formato longo: uma linha por nucleo + permeabilidade)
   Material ('Kool Mu','MPP','High Flux','XFlux','Kool Mu MAX','Kool Mu Hf','Edge'),
   PartNumber, Permeability, AL_nHesp2, Le_mm, Ae_mm2, Ve_mm3, OD_mm, ID_mm, HT_mm

Magnetics_CurveFit  (coeficientes por material + permeabilidade, do Curve-Fit-Equation-Tool)
   Material, Permeability,
   mi_a, mi_b, mi_c   (roll-off de permeabilidade: mu% = 1/(a + b*H^c)*100)
   P_a, P_b, P_c      (core-loss de Steinmetz: Pv = P_a * B^P_b * f_kHz^P_c [mW/cc])

Cores_Trafos  (a ALL-MODELS normalizada: uma linha por nucleo + material)
   Material ('R','P','F','T','N27'..'N97','139'), PartNumber, AL, Le, Ae_mm2,
   Ve_mm3, WaAc_cm4, OD_mm, ID_mm, Height_mm, Length_mm, LegLength_mm,
   Manufacturer, Geometry ('R'|'EE')

Steinmetz  (coeficientes de perda de nucleo do trafo, 13 materiais)
   MaterialID, Material, alpha, beta, k, c1_T, c2_T, c3_T, k_iGSE
   A ordem certa, vinda do coefficients.xlsx original, e col1=k, col2=alpha,
   col3=beta. Os materiais TDK (N27 a N97) ficam zerados aqui, porque usam a rede
   neural, e o '139' usa os coeficientes 'magmattec' da linha 13. A coluna Material
   e texto de proposito - o '139' como numero quebrava o strcmp.

AWG_Table
   AWG, r_ohm_m, A_cm2, D_cm  (resistencia, area e diametro por bitola)


4. As estruturas de dados principais
------------------------------------
op  (condicoes de operacao do semicondutor - entrada do +loss):
   MOSFET: .Vd .Tj .Rg .Vgson .I_RMS .I_on .I_off .fs .softSwitching
   Diodo : .Tj .I_RMS .I_avg

D  (o struct de projeto do magnetico - entrada do +design):
   Indutor: .Vd .ILmed .DeltaIL .ILef .L .IL_max .J .fs .r_awg .Aawg .Dextawg
            .temp_ambiente .DeltaTmax .kumin .kumax .MaxLoss .MaxVol
   Trafo  : .Vd .Vo .n .Ipef .Isef .fs .Ts .T .D .D2 .Rfio .Afio .Dfio .Rcfio
            .kumin .kumax .DeltaTmax .Bm .J .Pnucleomax .Vmax
            .kFaraday  (a constante de Faraday em Np=Vd*1e4/(k*Bm*fs*Ae); campo do usuario, padrao 9)

core  (o struct do nucleo - entrada do +design):
   Indutor: .id .mi_rel .le_mm .Ae_mm2 .Vol_mm3 .OD_mm .ID_mm .HT_mm .stacks
            (Magnetics: .mi_a .mi_b .mi_c .P_a .P_b .P_c)
            (Magmattec: .AL0_nHesp2 .pcore_fn)
   Trafo  : .partNumber .manufacturer .geometry .parallel .Ve_cm3 .Ae_cm2
            .Ap_cm4 .OD_cm .ID_cm .H_cm .Length_cm .LegLength_cm

records  (saida das abas MOSFET/Diodo, antes do dissipador):
   .PartNumber .Producer .Package .Technology .Vmax [.Imax] .P_total/.P_cond

hsAll  (o struct array dispositivo + dissipador, publicado para a densidade):
   .PartNumber .Producer .Technology .Heatsink .HeatsinkProducer .PowerW
   .Length_mm .Volume_cm3 .BlockVolt_V/.MaxVolt_V .Temp_Elev_C .Rth_C_W
   .Package .Method ('Natural'/'Forced') .AirSpeed
   .DevicesPerHS (Q)  .GroupLossW (= PowerW * Q, a perda do conjunto no dissipador)

proj  (saida do +design.inductor/transformer - um projeto):
   Indutor: .ID .mi .Ptotal .Pcore .Pcu .Vol .Ku .N .Nparal .DeltaT .Bp .fs ...
            (.N = NaN e .reason preenchido quando o projeto e rejeitado)
   Trafo  : .Material .Size .Geometry .ParallelCores .Np .Ns .PnucleoSE .Pcond
            .Ptrafo .DeltaT .VolTotal .Ku .Bm ...  (.Np = NaN quando rejeitado)

comp  (entrada do pdpwr.density): um struct com .mosfetI .mosfetII .diode .inductor
   .transformer (cada um uma tabela Identifier/PowerW/Volume_cm3) e
   .<familia>_mult (o multiplicador = numero de unidades/bracos).

res  (saida do pdpwr.density):
   .eff .powerDens .loss .lossDens .vol .idx .detail (.M1/.M2/.D/.L/.T) .metric


5. Como a interface e montada (+ui)
-----------------------------------
Em PowerDensityApp.m (a classdef): as propriedades publicas sao UIFigure, TabGroup
e Catalog; as privadas guardam os handles de cada aba (o struct ctx) e o Results
(o cache por familia). O construtor cria a uifigure invisivel, carrega o catalogo,
monta as 7 abas (MOSFET-I, MOSFET-II, Diodo, Indutor, Trafo, Power Density e About)
e so entao mostra a janela. O set_results(name, value) e o get_results(name) sao o
cache compartilhado.

Cada tab_*.m e uma funcao que monta a aba e devolve um struct ctx com os handles.
O padrao e sempre o mesmo:
   1. monta o painel de parametros (os spinners, via pdpwr.ui.spinner_row);
   2. monta as arvores de filtro (uitree com checkbox) ou o painel de status;
   3. monta o grafico (uiaxes) e a tabela (uitable), ja com cabecalhos visiveis;
   4. monta os botoes "Calculate" e "Filter / Plot";
   5. so no fim atribui os callbacks (ButtonPushedFcn) - por causa da armadilha #1.

As funcoes locais (privadas a cada arquivo, com prefixo i_):
   i_fieldList        define os spinners (name/label/default/limits/step)
   i_on_calculate     o callback do botao Calculate
   i_on_filter        o callback do botao Filter / Plot
   i_drawScatter      desenha o grafico (com os dataTips ricos)
   i_fillTable        preenche a uitable
   i_collectChecked   le os nos marcados nas arvores
   i_root             a raiz do projeto (sobe 4 niveis a partir do arquivo)

A convencao de eixos nas abas individuais e sempre volume no X e perdas no Y, com o
melhor ponto perto da origem. O grafico e grande (400x470) e a tabela e compacta,
embaixo, so como visualizacao secundaria.

A cor do scatter e uma por grupo, e a legenda usa um nome amigavel (via i_matLabel):
   - MOSFET/Diodo: por material (o campo Technology; hoje so 'SiC').
   - Indutor: por MaterialTag -> 'Kool Mu', 'MMT 052', etc.
   - Trafo: por Material -> 'Magnetics R/P/F/T', 'TDK N87', 'Magmattec 139'
     (os codigos crus R/P/F/T ficavam cripticos na legenda).

Os datatips sao compactos: cada ponto mostra so o essencial, com rotulos curtos
(Vol[cm3], Loss[W], Part/Mat/Pkg/HS/Cool, etc.), para a caixa caber dentro do
grafico. O detalhe completo fica na tabela.

No indutor e no trafo tem o dropdown "Show" (ctx.showDropdown): "All designs" (o
padrao) plota todos os projetos validos via i_applyShow (limitado a 15000 pontos,
mantendo os de menor perda, para nao travar), e "Best per core" mostra so o melhor
projeto de cada nucleo (i_bestPerCore).

Na aba Power Density, o eixo X e a eficiencia e o Y e a densidade (a orientacao do
app2 original, rerotulada por i_apply_mode). A vista padrao "Loss / Vol" poe Loss/Vol
no Y e reproduz o original; a "P_out / Vol" poe Pout/Vol. A eficiencia e
(P_out - perdas)/P_out. O datatip do grafico mostra so o "Combo #" (o numero da linha)
e as 4 metricas; a tabela e que traz a coluna "#" e, em cada celula de componente,
todos os detalhes construtivos (o i_identifier rico: produtor, encapsulamento,
dissipador com perfil, comprimento, Rth e ventilacao, Np/Ns/Bm/Ku/dT, mu/N/Nparal,
volume e perdas). O ponto i corresponde a linha i (o scatter e uma serie so). O
dropdown "Combinations" (ctx.comboDropdown) tem "Spread" (10 espalhados por familia),
"Top 10 best" e "All" (todos, com opts.MaxResults=1e6 e um uiconfirm de aviso).


6. Armadilhas conhecidas (vale ler antes de mexer)
--------------------------------------------------
#1  Closures capturam por valor. As abas montam o ctx aos poucos. Se voce setar o
    ButtonPushedFcn ja na criacao do botao, o callback recebe um ctx incompleto,
    sem os campos que so sao adicionados depois. A regra: crie todos os componentes,
    preencha o ctx inteiro e so entao atribua
    ctx.btn.ButtonPushedFcn = @(~,~) i_on_calculate(app, ctx). Se esquecer, o sintoma
    e um erro tipo "Unrecognized field tableCols", a tabela vazia e o Filter
    desabilitado.

#2  isvalid(uicontrol) da "Incorrect number or types of inputs" em alguns objetos de
    UI desta versao. Nao use isvalid em componentes; ponha close(pd), .Enable, .Value
    e .Message dentro de try/catch.

#3  O GSE do trafo tem integrais lentas e enche o Command Window de warnings de
    singularidade, o que trava tudo. Por isso ele so roda no detalhamento
    (gseEnabled=false na varredura); suprima os warnings 'MATLAB:integral:MinStepSize'
    e ':NonFiniteValue' e envolva em try/catch.

#4  A explosao combinatoria trava a UI no final (a uitable e o scatter congelam com
    30 mil pontos ou mais). No indutor e no trafo, a gente mostra so o melhor projeto
    de cada nucleo (i_bestPerCore, com chave Material|ID|Stacks); na densidade, cada
    familia entra limitada as 10 de menor perda (10^5 sets). O pdpwr.density pre-aloca
    um array do tamanho do produto, entao um CAP alto estoura a memoria.

#5  Nucleos com NaN na geometria: valide com i_isBadCore antes do loop.

#6  A ordem dos coeficientes de Steinmetz e k=col1, alpha=col2, beta=col3. Trocar
    alpha com k faz fs^alpha usar o expoente errado, o que gera perdas de 1e16 e faz
    o trafo rejeitar tudo. (O teste de regressao 8 guarda isso.)

#7  O material '139' vindo como numero do Excel quebra o strcmp(table.Material,'139').
    A solucao foi dupla: a coluna Material como texto e strcmp(string(...),material).

#8  No curve-fit do Magnetics, os blocos da esquerda (roll-off) e da direita
    (core-loss) do Curve-Fit-Equation-Tool nao estao alinhados linha a linha (o
    Kool Mu Hf da direita pula o mu90). Parseie cada bloco separado e junte por
    (material, permeabilidade). Os nomes usam caracteres especiais (mu, f script), que
    precisam ser normalizados para 'u' e 'f'. E use so os blocos de toroide (linhas
    ~9 a 81), ignorando as variantes E-core e EQ&LP.

#9  A pasta dos testes tem que se chamar '+test' (o pacote), senao test.regression nao
    resolve.

#10 Caminhos no .exe (deployment): nunca use mfilename('fullpath') para achar
    data/output. Funciona no MATLAB, mas quebra no .exe, porque os arquivos ficam sob
    o ctfroot. Sempre use pdpwr.util.data_root() (para catalogo, XML, rede neural e
    logo) e pdpwr.util.output_dir() (para gravar os resultados; o ctfroot e
    somente-leitura, entao ele grava em ~/PowerDensityTool/output). O data_root faz uma
    busca recursiva pelo Catalog.xlsx como fallback, porque o mcc espelha o caminho
    absoluto sob o ctfroot. Se esquecer disso, o sintoma no .exe e o erro "Figure
    handle 'Visible' value must be 'on'" - o catalogo nao carrega e o uialert acaba
    falhando numa figura invisivel.


7. Como estender
----------------
Para adicionar um MOSFET ou diodo novo: ponha o XML PLECS em
data/plecs_mosfets/<fabricante>/ (no caso do MOSFET) e adicione uma linha na aba
MOSFETs_PLECS ou Diodes do Catalog.xlsx, com a coluna Technology ('SiC', 'Si' ou
'GaN' - o scatter ja colore por material sozinho).

Para um dissipador novo: uma linha na aba Heatsinks, com o Rth natural e forcado, a
altura, a largura e as notas.

Para um material magnetico novo: no indutor, linhas em Cores_Magnetics (ou
Cores_Magmattec) mais os coeficientes em Magnetics_CurveFit (mi_a..c e P_a..c por
permeabilidade); no trafo, linhas em Cores_Trafos mais os coeficientes em Steinmetz
(ou a rede neural, no caso dos TDK).

Para um spinner novo numa aba: edite o i_fieldList daquela aba (name, label, default,
limits, step). O loop de construcao cria o uispinner sozinho.


8. Validacao e testes
---------------------
A bateria de regressao (auto-contida, 12 testes):
   cd src
   matlab -batch "test.regression"
Espera-se "=== Total failures: 0 ===". Ela cobre a carga do catalogo, a tabela AWG, o
Eon dos GeneSiC e Wolfspeed, o Pcond do diodo, o dispatch por material do Magmattec, o
Bpk com le, o mapeamento k/alpha do Steinmetz, a diferenciacao do curve-fit por
material, a combinacao de densidade, a cadeia termica do dissipador e a constante de
Faraday.

Para pegar erros de montagem da interface sem abrir a janela:
   cd src
   matlab -batch "app=PowerDensityApp; drawnow; disp('OK'); delete(app.UIFigure)"

E tem o smoke test rapido, o src/pdpwr_demo.m.


9. Compilar para .exe (precisa do MATLAB Compiler)
--------------------------------------------------
A ferramenta foi reescrita sem evalin/run em workspace base - o app2 original usava
evalin('base','run(...)'), o que inviabilizava o standalone. Todo o calculo esta em
+pdpwr e os caminhos passam por pdpwr.util.data_root()/output_dir(), que funcionam no
.exe (ver a armadilha #10). O ambiente testado foi MATLAB R2023b no Windows. Confira a
licenca com license('test','Compiler'), que deve dar 1.

O jeito recomendado e um comando so:
   cd src
   build_installer            % instalador 'web' (pequeno, baixa o Runtime na
                              %   instalacao) - use este
   build_installer('included')% instalador offline com o Runtime embutido (~2-4 GB;
                              %   o download e lento e costuma travar - evite)

O build_installer compila para um intermediario (build/app), empacota o instalador em
build/setup/MyAppInstaller.exe e, no fim, apaga o build/app - porque o .exe cru se
mostrou pouco confiavel em algumas maquinas e o certo e instalar pelo instalador. O
unico arquivo a distribuir e o build/setup/MyAppInstaller.exe (e ele vai publicado nos
Releases do GitHub, nao no historico do git).

Por baixo, o build_installer chama:
   compiler.build.standaloneApplication('PowerDensityApp.m', ...
       'AdditionalFiles', {+pdpwr, +test, ../data, ../assets}, 'OutputDir', app)
   compiler.package.installer(res, 'RuntimeDelivery','web', 'OutputDir', setup)

Se quiser so o .exe cru, sem instalador, da para usar o mcc classico (lembrando que
esse exe cru e o tal que nem sempre abre):
   mcc -m PowerDensityApp.m -a +pdpwr -a +test -a ../data -a ../assets -d ../build/app

O .exe e o Runtime sao so de Windows. Para Mac ou Linux, compile naquele sistema - o
codigo-fonte .m roda em qualquer um que tenha MATLAB. E, ao adicionar arquivos de
dados novos, inclua-os com -a (ou em AdditionalFiles) e acesse via
pdpwr.util.data_root(), nunca por caminho absoluto ou mfilename.
